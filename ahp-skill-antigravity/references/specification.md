# Спецификация skill: анализ альтернатив методом AHP / Саати

## 1. Назначение skill

Skill предназначен для проверки идеи анализа альтернатив через управляемый диалог с пользователем. Он помогает пользователю:

1. сформулировать задачу выбора;
2. определить цель проекта;
3. собрать и уточнить критерии;
4. зафиксировать направление каждого критерия;
5. собрать альтернативы;
6. провести попарные сравнения критериев;
7. провести попарные сравнения альтернатив по каждому критерию;
8. рассчитать веса критериев;
9. рассчитать локальные веса альтернатив по каждому критерию;
10. рассчитать итоговый рейтинг альтернатив;
11. проверить согласованность оценок;
12. показать Парето-фронтир альтернатив;
13. описать управленческую «ставку» каждой альтернативы;
14. выдать простой и понятный финальный вывод.

Skill является самостоятельным диалоговым инструментом. Его задача — провести пользователя через метод AHP, выполнить расчеты и объяснить результат понятным языком.

---

## 2. Ключевая идея

Skill работает по логике метода анализа иерархий AHP / Саати.

Главная цепочка:

```text
Цель выбора
→ критерии
→ направленные критерии
→ веса критериев
→ альтернативы
→ сравнение альтернатив по каждому критерию
→ локальные веса альтернатив
→ итоговый рейтинг
→ Парето-фронтир
→ ставка каждой альтернативы
→ простой финальный вывод
```

Важно:

```text
Критерии не «побеждают».
Критерии получают веса важности.
Побеждают альтернативы.
```

## 4. Рекомендуемые ограничения для теста

Чтобы диалог не стал слишком длинным, skill должен рекомендовать пользователю:

```text
Критерии: 3–7
Альтернативы: 2–5
```

Skill не должен жестко запрещать большее количество критериев или альтернатив, но обязан предупредить о росте числа сравнений.

Формула количества попарных сравнений:

```text
n × (n - 1) / 2
```

Пример:

```text
6 критериев = 6 × 5 / 2 = 15 сравнений критериев.
4 альтернативы = 4 × 3 / 2 = 6 сравнений альтернатив по каждому критерию.
Если критериев 6, то сравнений альтернатив будет 6 × 6 = 36.
Итого: 15 + 36 = 51 сравнение.
```

Skill должен заранее показать пользователю примерную нагрузку перед началом сравнений.

## 5. Роли skill в процессе

Skill выполняет четыре функции.

### 5.1. Модератор процесса

Skill ведет пользователя по этапам и не перескакивает через незавершенные шаги.

### 5.2. Методолог AHP

Skill следит, чтобы сравнения соответствовали методу Саати:

```text
сначала пользователь выбирает, что важнее / предпочтительнее;
затем указывает силу предпочтения по шкале Саати.
```

### 5.3. Расчетный модуль

Skill строит матрицы, считает веса, согласованность, итоговый рейтинг и Парето-фронтир.

### 5.4. Интерпретатор результата

Skill объясняет результат простым языком:

```text
почему победила конкретная альтернатива;
за счет каких критериев она победила;
какие альтернативы сильны, но делают другую ставку;
какие альтернативы доминируются;
насколько результату можно доверять.
```

## 6. Диалоговый сценарий

## Этап 0. Старт skill

Skill начинает с короткого объяснения процесса.

Пример сообщения:

```text
Мы проведем анализ альтернатив методом AHP / Саати.

Порядок работы:
1. Определим проект и цель выбора.
2. Соберем критерии.
3. Уточним, что по каждому критерию считается лучшим направлением.
4. Сравним критерии между собой.
5. Соберем альтернативы.
6. Сравним альтернативы по каждому критерию.
7. Рассчитаем итоговый рейтинг.
8. Покажем Парето-фронтир и ставку каждой альтернативы.
9. Сделаем простой финальный вывод.

Для первого теста лучше использовать 3–7 критериев и 2–5 альтернатив.
```

После этого skill задает первый вопрос.

## Этап 1. Название проекта

Skill спрашивает:

```text
Введите название проекта анализа альтернатив.
```

Пример ответа пользователя:

```text
Выбор CRM-системы
```

Skill сохраняет:

```text
project_name = "Выбор CRM-системы"
```

---

## Этап 2. Цель выбора

Skill спрашивает:

```text
Сформулируйте цель выбора одним предложением.
Например: "Выбрать оптимальную CRM-систему для отдела продаж".
```

Пример ответа пользователя:

```text
Выбрать CRM-систему для отдела продаж среднего бизнеса.
```

Skill сохраняет:

```text
goal = "Выбрать CRM-систему для отдела продаж среднего бизнеса."
```

Skill подтверждает:

```text
Зафиксировано:
Проект: Выбор CRM-системы
Цель: Выбрать CRM-систему для отдела продаж среднего бизнеса.
```

---

## Этап 3. Сбор критериев

Skill спрашивает:

```text
Введите критерии, по которым нужно сравнивать альтернативы.
Лучше указать 3–7 критериев.
Пишите каждый критерий с новой строки.
```

Пример ответа пользователя:

```text
Стоимость внедрения
Удобство для пользователей
Скорость внедрения
Интеграции
Риски
```

Skill сохраняет список критериев:

```text
criteria = [
  "Стоимость внедрения",
  "Удобство для пользователей",
  "Скорость внедрения",
  "Интеграции",
  "Риски"
]
```

---

## Этап 4. Предложение дополнительных критериев

После того как пользователь ввел критерии, skill анализирует полноту списка и может предложить дополнительные критерии.

Правило:

```text
Skill может предлагать критерии, но не имеет права добавлять их без подтверждения пользователя.
```

Пример сообщения:

```text
Вы указали такие критерии:
1. Стоимость внедрения
2. Удобство для пользователей
3. Скорость внедрения
4. Интеграции
5. Риски

Возможно, также стоит рассмотреть:
1. Масштабируемость
2. Стоимость сопровождения
3. Зависимость от поставщика
4. Качество поддержки
5. Простота обучения сотрудников

Хотите добавить что-то из этого списка или оставить текущий набор критериев?
```

Если пользователь подтверждает добавление, skill обновляет список критериев.

---

## Этап 5. Уточнение направления критериев

Перед сравнением критериев skill должен уточнить, что по каждому критерию считается лучшим направлением.

Это нужно, чтобы избежать двусмысленных вопросов вроде:

```text
Какая альтернатива более стоимостьная?
```

Вместо этого критерий должен стать направленным:

```text
меньшая стоимость внедрения;
большее удобство для пользователей;
меньшие риски;
большая скорость внедрения;
лучшие интеграции.
```

### 5.1. Формат вопроса

Skill спрашивает по каждому критерию:

```text
Критерий: Стоимость внедрения.
Что считается лучшим направлением?
A. Меньшая стоимость лучше.
B. Большая стоимость лучше.
C. Это качественный критерий, направление нужно сформулировать словами.
```

Пользователь отвечает:

```text
A
```

Skill сохраняет:

```json
{
  "name": "Стоимость внедрения",
  "direction": "lower_is_better",
  "question_label": "меньшая стоимость внедрения"
}
```

### 5.2. Варианты направления

Skill должен поддерживать три типа направления:

```text
higher_is_better — больше лучше;
lower_is_better — меньше лучше;
qualitative_preference — качественная экспертная предпочтительность.
```

Примеры:

```json
{
  "name": "Удобство для пользователей",
  "direction": "higher_is_better",
  "question_label": "большее удобство для пользователей"
}
```

```json
{
  "name": "Риски",
  "direction": "lower_is_better",
  "question_label": "меньшие риски"
}
```

```json
{
  "name": "Культурное соответствие",
  "direction": "qualitative_preference",
  "question_label": "лучшее культурное соответствие"
}
```

### 5.3. Правило формулировки вопросов по альтернативам

Skill должен использовать направленную формулировку критерия.

Плохо:

```text
Какая альтернатива лучше по критерию "Стоимость"?
```

Хорошо:

```text
Если смотреть только на критерий "меньшая стоимость внедрения",
какая альтернатива предпочтительнее для цели проекта?
```

## Этап 6. Утверждение финального списка критериев

Skill показывает финальный список критериев с направлением.

Пример:

```text
Финальный список критериев:
1. Стоимость внедрения — лучше меньшая стоимость.
2. Удобство для пользователей — лучше большее удобство.
3. Скорость внедрения — лучше большая скорость.
4. Интеграции — лучше более полные и надежные интеграции.
5. Риски — лучше меньшие риски.
```

Затем skill рассчитывает количество сравнений:

```text
Для 5 критериев потребуется 10 попарных сравнений.
```

Skill спрашивает:

```text
Подтверждаете этот список критериев и переход к сравнению критериев?
```

После подтверждения список критериев считается зафиксированным.

Правило:

```text
Если пользователь меняет список критериев после начала сравнений, skill должен предупредить, что сравнение критериев нужно начать заново.
```

---

## Этап 7. Попарное сравнение критериев

Skill сравнивает все пары критериев.

Для списка из `n` критериев нужно провести:

```text
n × (n - 1) / 2
```

сравнений.

### 7.1. Формат вопроса

Skill показывает два критерия и спрашивает, какой важнее относительно цели проекта.

Пример:

```text
Сравнение критериев 1 из 10.

Цель: выбрать CRM-систему для отдела продаж среднего бизнеса.

Что важнее для достижения этой цели?
A. Меньшая стоимость внедрения
B. Большее удобство для пользователей

Ответьте: A или B.
```

Пользователь отвечает:

```text
B
```

Skill уточняет силу предпочтения по 9-балльной шкале Саати.

```text
Насколько "большее удобство для пользователей" важнее, чем "меньшая стоимость внедрения"?

1 — одинаковая важность
2 — слабое промежуточное предпочтение
3 — умеренное предпочтение
4 — промежуточное предпочтение между 3 и 5
5 — сильное предпочтение
6 — промежуточное предпочтение между 5 и 7
7 — очень сильное предпочтение
8 — промежуточное предпочтение между 7 и 9
9 — абсолютное предпочтение

Введите число от 1 до 9.
```

Пользователь отвечает:

```text
5
```

Skill сохраняет:

```text
Большее удобство для пользователей важнее меньшей стоимости внедрения в 5 раз.
```

В матрице это означает:

```text
Удобство / Стоимость = 5
Стоимость / Удобство = 1/5
```

---

## Этап 8. Расчет весов критериев

После завершения всех сравнений критериев skill строит матрицу критериев и рассчитывает веса.

Skill выводит таблицу:

```markdown
| № | Критерий | Вес |
|---:|---|---:|
| 1 | Большее удобство для пользователей | 0.34 |
| 2 | Лучшие интеграции | 0.22 |
| 3 | Меньшая стоимость внедрения | 0.18 |
| 4 | Меньшие риски | 0.16 |
| 5 | Большая скорость внедрения | 0.10 |
```

Затем выводит показатель согласованности:

```text
Показатель согласованности CR = 0.07.
Оценки критериев согласованы. Можно продолжать.
```

Если `CR > 0.10`, skill предупреждает:

```text
Показатель согласованности CR = 0.16.
Есть сомнения в согласованности оценок. Желательно проверить сравнения критериев.
```

Если `CR > 0.20`, skill предупреждает жестче:

```text
Показатель согласованности CR = 0.24.
Оценки критериев противоречивы. Итоговый результат может быть ненадежным.
Рекомендуется пересмотреть часть сравнений.
```

## Этап 9. Сбор альтернатив

Skill спрашивает:

```text
Введите альтернативы, которые нужно сравнить.
Лучше указать 2–5 альтернатив.
Пишите каждую альтернативу с новой строки.
```

Пример ответа пользователя:

```text
CRM A
CRM B
CRM C
```

Skill показывает список:

```text
Список альтернатив:
1. CRM A
2. CRM B
3. CRM C
```

Skill рассчитывает количество сравнений:

```text
Для 3 альтернатив потребуется 3 сравнения по каждому критерию.
Так как критериев 5, всего потребуется 15 сравнений альтернатив.
```

Skill спрашивает:

```text
Подтверждаете список альтернатив и переход к сравнению альтернатив по критериям?
```

После подтверждения список альтернатив считается зафиксированным.

---

## Этап 10. Попарное сравнение альтернатив по каждому критерию

Skill проходит по каждому критерию и сравнивает все пары альтернатив внутри этого критерия.

Ключевое правило:

```text
Альтернативы сравниваются не вообще, а строго по конкретному направленному критерию.
```

### 10.1. Формат вопроса

Пример:

```text
Критерий: меньшая стоимость внедрения.
Сравнение альтернатив 1 из 3 по этому критерию.

Если смотреть только на критерий "меньшая стоимость внедрения",
какая альтернатива предпочтительнее для цели проекта?

A. CRM A
B. CRM B

Ответьте: A или B.
```

Пользователь отвечает:

```text
A
```

Skill уточняет силу предпочтения:

```text
Насколько "CRM A" предпочтительнее, чем "CRM B" по критерию "меньшая стоимость внедрения"?

1 — одинаково предпочтительны
2 — слабое промежуточное предпочтение
3 — умеренное предпочтение
4 — промежуточное предпочтение между 3 и 5
5 — сильное предпочтение
6 — промежуточное предпочтение между 5 и 7
7 — очень сильное предпочтение
8 — промежуточное предпочтение между 7 и 9
9 — абсолютное предпочтение

Введите число от 1 до 9.
```

Пользователь отвечает:

```text
3
```

Skill сохраняет:

```text
По критерию "меньшая стоимость внедрения": CRM A предпочтительнее CRM B в 3 раза.
```

В матрице это означает:

```text
CRM A / CRM B = 3
CRM B / CRM A = 1/3
```

---

## Этап 11. Расчет локальных весов альтернатив

Для каждого критерия skill строит отдельную матрицу альтернатив и рассчитывает локальные веса альтернатив.

Пример вывода:

```markdown
### Критерий: меньшая стоимость внедрения

| Альтернатива | Локальный вес |
|---|---:|
| CRM A | 0.60 |
| CRM B | 0.30 |
| CRM C | 0.10 |
```

Skill также рассчитывает `CR` для каждой матрицы альтернатив.

Пример:

```markdown
| Критерий | CR | Оценка качества |
|---|---:|---|
| Меньшая стоимость внедрения | 0.04 | хорошо |
| Большее удобство для пользователей | 0.16 | желательно проверить |
| Меньшие риски | 0.23 | ненадежно |
```

---

## Этап 12. Итоговый расчет альтернатив

После всех сравнений skill рассчитывает итоговый рейтинг альтернатив.

Формула:

```text
Итоговый балл альтернативы = сумма по всем критериям:
вес критерия × локальный вес альтернативы по этому критерию
```

Формально:

```text
Score(alternative_j) = Σ wc_k × wa_jk
```

Где:

```text
wc_k — вес критерия k;
wa_jk — локальный вес альтернативы j по критерию k.
```

Skill выводит итоговую таблицу:

```markdown
| Место | Альтернатива | Итоговый вес |
|---:|---|---:|
| 1 | CRM B | 0.46 |
| 2 | CRM A | 0.34 |
| 3 | CRM C | 0.20 |
```

Затем выводит расчетную рекомендацию:

```text
Расчетная рекомендация по AHP: CRM B.
```

---

## Этап 13. Парето-фронтир альтернатив

После AHP-расчета skill должен выполнить дополнительный аналитический слой — проверку Парето-фронтира.

Важно:

```text
AHP считает итоговый рейтинг.
Парето-фронтир объясняет структуру компромиссов между альтернативами.
```

Парето-фронтир не заменяет AHP и не меняет итоговый вес. Он помогает понять, есть ли среди альтернатив очевидно слабые варианты.

---

## 13.1. Смысл Парето-фронтира простым языком

Skill должен объяснять пользователю:

```text
Парето-фронтир — это набор альтернатив, которые нельзя однозначно назвать хуже других.
Если альтернатива находится на Парето-фронтире, значит у нее есть своя сильная сторона.
Она может проигрывать по одним критериям, но выигрывать по другим.
```

Простое объяснение:

```text
Если одна альтернатива не хуже другой по всем критериям и лучше хотя бы по одному критерию, то вторая альтернатива доминируется.
Доминируемая альтернатива — это вариант, который выглядит слабее другого варианта по всей совокупности критериев.
```

---

## 13.2. Математическая проверка доминирования

После расчета локальных весов альтернатив skill имеет матрицу:

```text
Альтернатива × Критерии
```

Пример:

```markdown
| Альтернатива | Стоимость | Удобство | Интеграции |
|---|---:|---:|---:|
| CRM A | 0.60 | 0.20 | 0.20 |
| CRM B | 0.30 | 0.50 | 0.60 |
| CRM C | 0.10 | 0.30 | 0.20 |
```

Так как локальные веса уже построены по направленным критериям, большее значение означает, что альтернатива лучше по этому критерию.

Альтернатива `X` доминирует альтернативу `Y`, если:

```text
X >= Y по всем критериям
и
X > Y хотя бы по одному критерию.
```

Формально:

```text
X dominates Y if:
∀k: wa_Xk >= wa_Yk
and
∃k: wa_Xk > wa_Yk
```

Где:

```text
wa_Xk — локальный вес альтернативы X по критерию k;
wa_Yk — локальный вес альтернативы Y по критерию k.
```

Альтернатива входит в Парето-фронтир, если ее не доминирует ни одна другая альтернатива.

---

## 13.3. Формат вывода Парето-фронтира

Skill выводит:

```markdown
## Парето-фронтир

Альтернативы на Парето-фронтире:
- CRM A
- CRM B

Доминируемые альтернативы:
- CRM C
```

Если все альтернативы находятся на фронтире:

```text
Все альтернативы находятся на Парето-фронтире.
Это означает, что среди них нет очевидно слабого варианта.
Каждая альтернатива имеет свою сильную сторону, а итоговый выбор зависит от весов критериев.
```

Если победитель AHP не находится на Парето-фронтире, skill должен предупредить:

```text
Внимание: расчетный победитель AHP не находится на Парето-фронтире.
Это необычная ситуация. Рекомендуется проверить локальные веса и согласованность сравнений.
```

В нормальной ситуации расчетный победитель обычно должен быть недоминируемой альтернативой.

## Этап 14. Ставка каждой альтернативы

После Парето-фронтира skill должен описать «ставку» каждой альтернативы.

---

## 14.1. Смысл ставки альтернативы

Skill должен объяснять термин простым языком:

```text
Ставка альтернативы — это ответ на вопрос:
за счет чего эта альтернатива пытается выиграть выбор?
```

Иначе:

```text
Ставка показывает, на какие сильные стороны опирается альтернатива и какой компромисс она предлагает.
```

Примеры:

```text
CRM A делает ставку на низкую стоимость и скорость внедрения.
CRM B делает ставку на удобство пользователей и интеграции.
CRM C делает ставку на масштабируемость, но проигрывает по цене и скорости.
```

---

## 14.2. Как определить сильные и слабые критерии альтернативы

В MVP используется простое правило.

Сильные критерии альтернативы:

```text
критерии, по которым альтернатива занимает 1 место по локальному весу.
```

Слабые критерии альтернативы:

```text
критерии, по которым альтернатива занимает последнее место по локальному весу.
```

Дополнительное правило:

```text
Если альтернатива не занимает 1 место ни по одному критерию, но находится близко к лидеру по важному критерию, skill может отметить это как умеренную сильную сторону.
```

# 15. Математический аппарат skill

## 15.1. Шкала Саати

В финальной спецификации используется классическая 9-балльная шкала Саати.

| Значение | Интерпретация |
|---:|---|
| 1 | одинаковая важность / одинаковое предпочтение |
| 2 | слабое промежуточное предпочтение |
| 3 | умеренное предпочтение |
| 4 | промежуточное предпочтение между 3 и 5 |
| 5 | сильное предпочтение |
| 6 | промежуточное предпочтение между 5 и 7 |
| 7 | очень сильное предпочтение |
| 8 | промежуточное предпочтение между 7 и 9 |
| 9 | абсолютное предпочтение |

Skill должен использовать эту шкалу и для сравнения критериев, и для сравнения альтернатив по критериям.

---

## 15.2. Матрица попарных сравнений

Для каждого набора объектов строится квадратная матрица `A` размера `n × n`.

Объектами могут быть:

```text
критерии;
альтернативы внутри конкретного критерия.
```

Свойства матрицы:

```text
aᵢᵢ = 1
```

Если объект `i` предпочтительнее объекта `j` с интенсивностью `x`, то:

```text
aᵢⱼ = x
aⱼᵢ = 1 / x
```

Где:

```text
x ∈ {1, 2, 3, 4, 5, 6, 7, 8, 9}
```

Пример:

```text
Если критерий "большее удобство" важнее критерия "меньшая стоимость" в 5 раз:

Удобство / Стоимость = 5
Стоимость / Удобство = 1/5
```

---

## 15.3. Расчет весов через собственный вектор

Для матрицы попарных сравнений `A` рассчитывается главный собственный вектор. В реализации используется итеративный алгоритм: стартовый вектор весов многократно умножается на матрицу и нормализуется до сходимости.

```text
A x -> y
x = y / sum(y)
```

Итоговый нормализованный вектор:

```text
w = [w₁, w₂, ..., wₙ]
```

Сумма весов должна быть равна 1:

```text
Σwᵢ = 1
```

Для проверки согласованности используется приближенное значение главного собственного числа:

```text
λmax
```

Для вывода пользователю веса можно округлять до 2–4 знаков после запятой. В расчетах должны использоваться неокругленные значения.

---

## 15.4. Расчет согласованности

Для проверки согласованности используется показатель `CR`.

Сначала рассчитывается произведение матрицы на вектор весов:

```text
A × w
```

Затем для каждого элемента рассчитывается:

```text
λᵢ = (A × w)ᵢ / wᵢ
```

Далее:

```text
λmax = среднее значение λᵢ
```

Индекс согласованности:

```text
CI = (λmax - n) / (n - 1)
```

Отношение согласованности:

```text
CR = CI / RI
```

Где:

```text
n — размер матрицы;
RI — случайный индекс Саати.
```

Таблица `RI`:

| n | RI |
|---:|---:|
| 1 | 0.00 |
| 2 | 0.00 |
| 3 | 0.58 |
| 4 | 0.90 |
| 5 | 1.12 |
| 6 | 1.24 |
| 7 | 1.32 |
| 8 | 1.41 |
| 9 | 1.45 |
| 10 | 1.49 |

Для `n = 1` и `n = 2`:

```text
CR = 0
```

Интерпретация:

```text
CR <= 0.10 — хорошая согласованность;
0.10 < CR <= 0.20 — есть сомнения, желательно проверить;
CR > 0.20 — оценки противоречивы, результат может быть ненадежным.
```

---

## 15.5. Расчет весов критериев

После сравнения критериев строится матрица критериев `C`.

Из нее рассчитывается вектор весов критериев:

```text
Wc = [wc₁, wc₂, ..., wcₙ]
```

Где:

```text
wc_k — вес критерия k.
```

Пример:

```text
Меньшая стоимость = 0.20
Большее удобство = 0.35
Большая скорость = 0.15
Меньшие риски = 0.30
```

---

## 15.6. Расчет локальных весов альтернатив

Для каждого критерия строится отдельная матрица альтернатив.

Пример:

```text
Матрица альтернатив по критерию "меньшая стоимость внедрения".
Матрица альтернатив по критерию "большее удобство".
Матрица альтернатив по критерию "меньшие риски".
```

Для каждой матрицы рассчитывается локальный вектор весов альтернатив:

```text
Wa_k = [wa₁k, wa₂k, ..., waₘk]
```

Где:

```text
k — номер критерия;
m — количество альтернатив;
wa_jk — локальный вес альтернативы j по критерию k.
```

Пример:

```text
Критерий: меньшая стоимость внедрения

CRM A = 0.55
CRM B = 0.30
CRM C = 0.15
```

---

## 15.7. Расчет итогового рейтинга альтернатив

Итоговый вес альтернативы считается как взвешенная сумма локальных весов альтернатив по критериям.

Формула:

```text
Score(alternative_j) = Σ wc_k × wa_jk
```

Где:

```text
wc_k — вес критерия k;
wa_jk — локальный вес альтернативы j по критерию k.
```

Итоговые веса альтернатив должны суммироваться к 1:

```text
Σ Score(alternative_j) = 1
```

Победителем считается альтернатива с максимальным итоговым весом.

---

## 15.8. Математика Парето-фронтира

Для каждой альтернативы есть набор локальных весов по критериям:

```text
Alternative_j = [wa_j1, wa_j2, ..., wa_jk]
```

Альтернатива `X` доминирует альтернативу `Y`, если:

```text
∀k: wa_Xk >= wa_Yk
и
∃k: wa_Xk > wa_Yk
```

Альтернатива входит в Парето-фронтир, если:

```text
не существует другой альтернативы, которая ее доминирует.
```

Skill должен помнить:

```text
Парето-фронтир строится по локальным весам альтернатив по критериям,
а не по итоговым AHP-баллам.
```

# 17. Правила поведения skill

## 17.1. Правило последовательности

Skill не должен переходить к следующему этапу, если текущий этап не завершен.

```text
Нельзя сравнивать критерии, пока не утвержден финальный список критериев.
Нельзя сравнивать критерии, пока не уточнено направление каждого критерия.
Нельзя сравнивать альтернативы, пока не рассчитаны веса критериев.
Нельзя считать итоговый рейтинг, пока не завершены все сравнения альтернатив по каждому критерию.
```

---

## 17.2. Правило подтверждения

Skill должен получать подтверждение пользователя перед переходом к большим этапам:

```text
после финального списка критериев;
после уточнения направлений критериев;
после финального списка альтернатив;
перед финальным расчетом.
```

---

## 17.3. Правило неизменности списков

После начала сравнений список объектов нельзя менять без предупреждения.

Если пользователь хочет изменить критерии после начала сравнения критериев, skill отвечает:

```text
Можно изменить список критериев, но тогда текущие сравнения критериев станут недействительными и этап сравнения нужно будет начать заново.
```

Если пользователь хочет изменить альтернативы после начала сравнения альтернатив, skill отвечает:

```text
Можно изменить список альтернатив, но тогда текущие сравнения альтернатив станут недействительными и этап сравнения альтернатив нужно будет начать заново.
```

---

## 17.4. Правило неполных данных

Skill не должен считать финальный результат, если не заполнены обязательные сравнения.

Если данных не хватает, skill сообщает:

```text
Финальный расчет пока невозможен. Не хватает следующих сравнений:
1. Критерий "меньшая стоимость внедрения": CRM A vs CRM C.
2. Критерий "меньшие риски": CRM B vs CRM C.
```

---

## 17.5. Правило математической строгости

Skill не должен заменять AHP простым голосованием, субъективным рассуждением или текстовым ранжированием.

Обязательный расчет:

```text
попарные сравнения
→ матрицы
→ веса
→ согласованность
→ итоговый рейтинг
→ Парето-фронтир
→ интерпретация
```

---

## 17.6. Правило работы с несогласованностью

Если `CR > 0.10`, skill должен предупредить пользователя.

Если `CR > 0.20`, skill должен явно сказать, что результат может быть ненадежным.

Skill может предложить:

```text
пересмотреть сравнения;
уменьшить количество критериев;
уточнить смысл критериев;
проверить противоречивые предпочтения.
```

В первой версии skill не обязан автоматически находить минимальный набор сравнений для исправления, но обязан предупредить о качестве результата.

---

## 17.7. Правило простого финального объяснения

Skill обязан делать финальный вывод простым языком.

Если используются термины, skill должен объяснить их.

Обязательные термины для объяснения:

```text
вес критерия;
локальный вес альтернативы;
итоговый вес альтернативы;
согласованность CR;
Парето-фронтир;
доминируемая альтернатива;
ставка альтернативы.
```

Пример простого объяснения:

```text
Вес критерия показывает, насколько этот критерий важен в общей задаче выбора.
Итоговый вес альтернативы показывает, насколько хорошо альтернатива выглядит с учетом всех критериев и их важности.
Парето-фронтир показывает альтернативы, которые нельзя назвать однозначно хуже других.
```

---

## 17.8. Правило ограничения результата

Skill должен объяснять результат как вывод внутри заданной модели, а не как абсолютную истину.

Обязательная формулировка:

```text
Результат показывает приоритеты внутри заданной модели выбора и введенных экспертных суждений. Он зависит от выбранных критериев, альтернатив и согласованности оценок.
```

---

# 18. Формат финального вывода

Финальный ответ skill должен содержать следующие блоки.

---

## 18.1. Проект и цель

```text
Проект: ...
Цель: ...
```

---

## 18.2. Критерии и их веса

```markdown
| № | Критерий | Направление | Вес |
|---:|---|---|---:|
| 1 | Стоимость внедрения | меньшая стоимость лучше | 0.22 |
| 2 | Удобство | большее удобство лучше | 0.34 |
```

Простое объяснение:

```text
Вес критерия показывает, насколько сильно этот критерий влияет на итоговый выбор.
Чем выше вес, тем сильнее критерий влияет на итоговый рейтинг альтернатив.
```

---

## 18.3. Согласованность критериев

```text
CR критериев = 0.07 — оценки согласованы.
```

Простое объяснение:

```text
CR показывает, насколько ваши сравнения не противоречат друг другу.
Если CR меньше или равен 0.10, результат обычно можно считать согласованным.
```

---

## 18.4. Локальные веса альтернатив по критериям

```markdown
### Критерий: меньшая стоимость внедрения

| Альтернатива | Локальный вес |
|---|---:|
| CRM A | 0.60 |
| CRM B | 0.30 |
| CRM C | 0.10 |
```

Простое объяснение:

```text
Локальный вес показывает, насколько альтернатива сильна только по одному конкретному критерию.
```

## 18.5. Согласованность альтернативных сравнений

```markdown
| Критерий | CR | Оценка качества |
|---|---:|---|
| Меньшая стоимость внедрения | 0.04 | хорошо |
| Большее удобство | 0.16 | желательно проверить |
| Меньшие риски | 0.23 | ненадежно |
```

## 18.6. Итоговый рейтинг альтернатив

```markdown
| Место | Альтернатива | Итоговый вес |
|---:|---|---:|
| 1 | CRM B | 0.46 |
| 2 | CRM A | 0.34 |
| 3 | CRM C | 0.20 |
```

Простое объяснение:

```text
Итоговый вес показывает общий результат альтернативы с учетом всех критериев и их важности.
```

## 18.7. Парето-фронтир

```markdown
## Парето-фронтир

Альтернативы на Парето-фронтире:
- CRM A
- CRM B

Доминируемые альтернативы:
- CRM C
```

Простое объяснение:

```text
Альтернативы на Парето-фронтире нельзя назвать однозначно хуже других.
Доминируемая альтернатива — это вариант, который уступает другой альтернативе по всем или почти всем ключевым направлениям сравнения.
```

---

## 18.8. Ставка каждой альтернативы

```markdown
| Альтернатива | Сильные критерии | Слабые критерии | Ставка альтернативы |
|---|---|---|---|
| CRM A | Меньшая стоимость, скорость | Интеграции | Быстро и дешевле внедрить |
| CRM B | Удобство, интеграции | Стоимость | Более качественное системное решение |
| CRM C | Масштабируемость | Стоимость, скорость | Долгосрочная архитектурная ставка |
```

Простое объяснение:

```text
Ставка альтернативы показывает, за счет чего этот вариант пытается выиграть выбор и какой компромисс предлагает.
```

---

## 18.9. Рекомендация

```text
Расчетная рекомендация: CRM B.
```

## 18.10. Простое финальное объяснение

Skill должен завершать вывод понятным объяснением.

Пример:

```text
CRM B получила лучший итоговый результат, потому что она сильнее других альтернатив по критериям, которые оказались наиболее важными: удобство пользователей и интеграции.

CRM A выглядит сильной альтернативой, если главным становится быстрое и дешевое внедрение. Но в вашей модели эти критерии имеют меньший вес, поэтому CRM A не стала первой.

CRM C делает ставку на масштабируемость, но проигрывает по нескольким более важным критериям. Поэтому она оказалась ниже в итоговом рейтинге.
```

## 18.11. Ограничение результата

Skill обязательно добавляет:

```text
Результат показывает приоритеты внутри заданной модели выбора и введенных экспертных суждений. Он не является абсолютной истиной и зависит от качества критериев, альтернатив и согласованности сравнений.
```

# 20. Критерий успешной проверки идеи

Skill считается успешным, если пользователь может:

1. Понять процесс без глубокого знания AHP.
2. Сформулировать цель выбора.
3. Ввести критерии.
4. Утвердить критерии после предложений skill.
5. Уточнить направление каждого критерия.
6. Пройти попарные сравнения критериев.
7. Ввести альтернативы.
8. Пройти попарные сравнения альтернатив по каждому критерию.
9. Получить расчетный результат.
10. Понять, почему победила конкретная альтернатива.
11. Увидеть, насколько согласованны его оценки.
12. Понять, какие альтернативы находятся на Парето-фронтире.
13. Понять ставку каждой альтернативы.
14. Получить простой финальный вывод без перегруза математическими терминами.

# 21. Краткое резюме спецификации

Skill должен вести пользователя по логике анализа альтернатив и давать расчетный результат.

Главная цепочка:

```text
Цель
→ критерии
→ направление критериев
→ сравнение критериев
→ веса критериев
→ альтернативы
→ сравнение альтернатив по каждому критерию
→ локальные веса
→ итоговый рейтинг
→ Парето-фронтир
→ ставка альтернатив
→ простой финальный вывод
```

Главное математическое ядро:

```text
Матрицы попарных сравнений
→ собственный вектор весов
→ нормализация весов
→ проверка согласованности CR
→ взвешенная сумма альтернатив
→ проверка Парето-доминирования
```

Главный принцип поведения:

```text
Skill не рассуждает вместо расчета.
Skill ведет пользователя через сравнения и считает результат по формальным правилам AHP.
```

Главный принцип финального вывода:

```text
Финальный вывод должен быть понятен пользователю без знания математики.
Если используются термины, skill обязан объяснить их простым языком.
```
